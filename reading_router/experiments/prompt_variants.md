# Reading Router Prompt Variants

目标：固定保留六步 `reading_chain`。路由逻辑在代码里做，prompt 本身不强调题型，不写“这是多选题/这是判断题/这是计算题”。

所有 prompt 都只要求输出：

```json
[
  {
    "qid": "...",
    "reading_chain": [
      "1任务...",
      "2对象...",
      "3主题...",
      "4变量...",
      "5关系/口径...",
      "6易错..."
    ]
  }
]
```

不要求 `reading_summary`、`notes`。六步是 intentionally doing，用来把 GPTPro 的自然读题过程展开成可控结构。

## Multi Choice Prompt

```text
六步读题,只用题干,不答题。输入i为qid。
JSON数组:[{"qid":"...","reading_chain":["1任务...","2对象...","3主题...","4变量...","5关系/口径...","6易错..."]}]
规则:
1写清题干要求核对什么结论或描述;
2写清涉及的文档、主体、产品、公司、法规或报告对象;
3写清真正要核对的主题维度;
4摘出题干里的关键条件、时间、数字、术语和限定词;
5写清跨文档/跨主体/跨年度/总分/并列/比较/存在关系;
6写一个最容易误读的核对点,尤其注意每个候选陈述都要独立核对。
禁补题外事实。
Q=...
```

## Single Choice Prompt

```text
六步读题,只用题干,不答题。输入i为qid。
JSON数组:[{"qid":"...","reading_chain":["1任务...","2对象...","3主题...","4变量...","5关系/口径...","6易错..."]}]
规则:
1写清题干要求找怎样的完整准确表述;
2写清涉及的文档、主体、产品、公司、法规或报告对象;
3写清真正要核对的主题维度;
4摘出题干里的关键条件、时间、数字、术语和限定词;
5写清对象归属、比较关系、计算口径、时间口径或适用范围;
6写一个最容易误读的核对点,尤其注意对象、归属、数字、时间或口径只要一处不准,整句就不完整准确。
禁补题外事实。
Q=...
```

## True False Prompt

```text
六步读题,只用题干,不答题。输入i为qid。
JSON数组:[{"qid":"...","reading_chain":["1任务...","2对象...","3主题...","4变量...","5关系/口径...","6易错..."]}]
规则:
1写清题干里的完整陈述在要求确认什么;
2写清陈述涉及的文档、主体、产品、公司、法规或报告对象;
3写清陈述真正落在哪些核对主题上;
4摘出陈述里的主体、时间、数字、术语、限定条件和否定条件;
5把陈述拆成若干条件,写清它们之间的并列、递进、比较、存在/不存在、时间先后或整体成立关系;
6写一个最容易误读的核对点,尤其注意不能只核对其中一部分。
禁补题外事实。
Q=...
```

## Numeric Prompt

```text
六步读题,只用题干,不答题。输入i为qid。
JSON数组:[{"qid":"...","reading_chain":["1任务...","2对象...","3主题...","4变量...","5关系/口径...","6易错..."]}]

1写清题干要求核对、比较、计算或排序什么;

3写清真正要核对的指标、费用、金额、比例、数量或规则;
```

## Routing Notes

路由说明只给代码和实验报告看，不进 prompt。

```text
multi_choice -> Multi Choice Prompt
single_choice -> Single Choice Prompt
true_false -> True False Prompt
numeric -> Numeric Prompt
reasoning -> Reasoning Prompt
```

数字路由只看结构：题干存在数字，排除 `19xx`、`20xx` 这类年份数字。其他业务词不参与路由。
